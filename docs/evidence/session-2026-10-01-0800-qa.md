## Independent implementation review

QA inspected the changed application and HTML against the interaction contract. The home link intercepts ordinary activation during play/result and opens the same restart confirmation as the two restart buttons. Modified/new-window link behavior is preserved. Restart explicitly focuses Keep playing; each trigger is retained for cancellation. Confirmed reset clears transient input/errors and gives the fresh intro control ownership of focus. All rendered main regions have `tabindex="-1"` for the skip link.

Custom-form validation reads the actual field value on submission and uses an explicit handler rather than native constraint bubbles. It checks the raw 1,200-code-unit maximum and trimmed 20-code-unit minimum, matching engine validation. Invalid text remains in the field, receives visible associated feedback and `aria-invalid`, and returns focus to the field without committing. Input revalidation clears corrected feedback. Proposal opening focuses the checked radio or, when no suggestion exists, the first radio without selecting it. Missing selection has visible associated feedback and focuses that first radio.

General action errors use connected page/dialog containers and visible text plus the announcement. Recovery wording distinguishes a rejected action before a state replacement from a failure after a state change; it does not promise rollback after a changed state. Optional mutating page-tool wrappers also surface and rethrow failures; the read-only snapshot tool is not wrapped. These are source findings; runtime behavior is recorded separately below.
