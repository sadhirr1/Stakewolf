## Independent test design and source review

The agreed `loadApplication(loader)` seam awaits actual module evaluation and
returns a small ready/failed result. The browser adapter separately restores the
static recovery node, checks that real initialization produced the new main/Start,
and controls Help and fallback focus. The tests do not invent a browser DOM.

Nine startup tests cover:

- A real module loaded behind a controlled pending promise: ready is withheld
  until evaluation completes, and the loader runs once.
- Actual missing entry, missing transitive dependency, invalid module syntax,
  throwing initializer and rejected asynchronous initializer. Raw imports are
  first asserted to fail for the intended reason, then the loader's handled result
  is verified. Diagnostic text is not exposed in the returned result.
- A synchronous loader failure followed by a separately loaded successful module.
  This does not claim a failed browser module cache can recover without a reload.
- Shipped HTML semantics: a focusable static skip destination, same-page native
  reload link, fresh-attempt/no-save consequence, no premature Start control,
  native no-script guidance and an external bootstrap entry. These are static
  response checks, not an executed JavaScript-disabled browser test.

The existing server check now verifies exact bytes and browser-usable MIME for all
six allowed game assets, including bootstrap. One additional test inspects actual
HTTP CSP headers on startup assets: scripts remain same-origin-only, connections
and objects stay prohibited, and no inline-script or arbitrary helper route is
enabled. Existing traversal, repository denial, query and HEAD checks remain.
Server tests use temporary loopback listeners that close after their test; QA did
not start a persistent game server. Temporary module fixtures are removed only
after checking their resolved parent and task-specific directory prefix.

QA independently inspected the bootstrap, index and server changes. The static
fallback and link remain available if bootstrap itself cannot load. Import,
dependency or initializer failure restores the original node after partial app
replacement, hides Help and presents recovery text. Successful startup requires a
new main and Start; focus moves only when a removed fallback held it. CSP is
unchanged, and only the new explicit bootstrap asset is added to the server map.
No blocking source-review finding was identified. Actual DOM restoration and focus
remain separate browser verification.

Development independently reviewed the new tests and server additions and
approved them. An initial review comment alleged an undefined `reload` variable;
the exact existing assignment was re-read and the finding withdrawn without any
test edit. No failed test execution is invented from that review comment.
