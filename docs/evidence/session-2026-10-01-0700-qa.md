## Independent contrast calculations

QA recalculated all 14 palette pairs listed in the visual specification from literal hexadecimal colors. Every result matched the specification's rounded value. Method: convert sRGB channels to linear light using the 0.04045 threshold, calculate relative luminance with weights 0.2126/0.7152/0.0722, then use `(lighter + 0.05) / (darker + 0.05)`. Ratios below are rounded for reporting; pass decisions use the unrounded result.

| Meaningful final pair | Ratio |
| --- | --- |
| Primary text / panel | 15.0216:1 |
| Supporting text / selected surface | 6.4552:1 |
| Primary action ink / lime | 13.5205:1 |
| Selected label / selected surface | 11.4864:1 |
| Placeholder / field | 8.2282:1 |
| Disabled text / disabled surface | 7.3999:1 |
| Disabled border / disabled surface | 3.1131:1 |
| Control border / selected surface | 3.4760:1 |
| Control border / question surface | 3.4771:1 |
| Control border / field | 4.4307:1 |
| Lime focus ring / dialog surface | 13.0971:1 |
| Lime focus ring / raised surface | 12.1471:1 |

These solid-color pairs meet the project's 4.5:1 meaningful-text and 3:1 control/focus targets. They do not certify every pixel, native radio rendering, overlay, state, focus geometry or complete accessibility. The method and thresholds were checked against W3C's [Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) and [Non-text Contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) guidance.

For comparison, the inherited control-border color produced only 1.565:1 against the panel. Compositing the old whole-button opacity of 0.45 gave approximately 3.762:1 for disabled question text and 2.672:1 for disabled stakeholder descriptions. Those disabled examples motivated a readability improvement; inactive controls are exempt from the cited text-contrast requirement, so they are not reported as an automatic WCAG failure. The final treatment uses solid text/background colors and full opacity.
