# SCRUM-20 visual directions — review handoff

These are original, static visual explorations for the Stakewolf opening and a dense investigation screen. They are **concepts**, not implemented gameplay, and neither is approved. Both are standalone HTML files with embedded CSS and no build, network, font, image, or JavaScript dependency.

## A — Signal / Noise

[Open concept A](signal-noise.html). A cinematic near-black stage uses large compressed typography, one acid-lime accent, perspective-rendered case-file geometry, and a circular promise stamp. The investigation screen keeps the dossier mood but organizes claims, sourced evidence and next questions in a high-density three-column desk. It develops the existing dark Stakewolf identity into a more striking opening. Risk: dramatic large type and layered geometry could crowd smaller displays; the working implementation would need careful motion restraint and source/text hierarchy.

## B — The Archive

[Open concept B](the-archive.html). An editorial off-white canvas contrasts with a midnight file cabinet, rust-red annotations, paper slips and an oversized serif headline. The investigation view evokes annotated documents, with source and time plainly shown. Its lighter reading surface may help long-form investigation, and its visual difference from A makes owner review a meaningful choice. Risk: the light palette is a departure from the existing dark visual system and would require a deliberate migration of all dialogue, backlog, result and error states.

## Shared rules and provenance

- Each mockup contains an opening and a **post-interview comparison** state using **illustrative excerpts from the draft case**, aligned in source with [KB-01/02/03](../case-design-v2.md) and the current [scenario](../../public/scenario.js): a Monday brief with a Wednesday target, 600 waitlisted teams versus 20 onboarded, and 3 of 40 reviewed long meetings missing an action owner on `relay-beta-17`. This assumes the player has already acquired KB-02/03 through the respective interviews; it is not an opening-state reveal. The follow-up prompts ask about launch scope and operating/verifying the review gate rather than re-asking known facts. This material illustrates layout; it does not define new scenario truth or acceptance behavior. The interpretation area is a dashed, labelled **concept-only** display, not a working control.
- Each shows a source/time for records and explicitly warns that conflicting evidence does not prove intent. The desired mechanic is judgment under uncertainty.
- Both stack the investigation columns on narrow widths; headings and cards wrap, and there is a 340px stress rule. `prefers-reduced-motion` disables the only optional smooth scrolling. Keyboard focus uses a visible outline, and the skip link becomes visible on focus through CSS without JavaScript.
- Typography uses system Arial/Georgia fallbacks. All perspective cards, folders, grid lines, stamps, colors and borders are original CSS/text. No asset, code, layout, or animation was copied from the inspiration site.
- Further implementation must preserve readable controls and verified contrast, actual 200% browser zoom, reduced-motion behavior, real game state, and a source-linked debrief. Static concepts cannot establish those properties.

## Screenshot feedback and first-screen revision

The owner supplied screenshots of both opening concepts at a zoom-like/narrow effective viewport. In those captures, the full case-file illustration had stacked below the opening and was invisible in the first screen. Signal / Noise also placed its entry action near or below the visible edge. The Archive left a large blank area beside the headline and felt less distinctive than intended. These are observations about the **pre-revision screenshots** supplied by the owner, not verification of the revised files.

Both openings now add an original compact case-file cue beside the headline at intermediate/zoom-like widths, while retaining the full illustration farther down. At phone widths the cue becomes a short inline record so it cannot obscure reading text. The headline and vertical gaps become smaller in the stacked layout, and the introductory action follows the copy without a fixed-height container. In The Archive, the compact navy/red record and condensed two-line headline use the previously blank area; its full paper folder remains a second reveal. The layouts still allow natural vertical scrolling at 200% zoom and do not clip text to force the action into a particular screenshot. These changes are source-level only and need new rendered desktop/narrow/zoom checks.

The owner then supplied five new screenshots at about 1800×900: each full desktop hero and each investigation screen, plus a scrolled view showing Signal / Noise's entry action. The investigation screens were readable, and both original full-size case-file illustrations appeared on desktop. However, both hero entry actions sat below the first desktop viewport. A **desktop-only** refinement now starts Signal / Noise's hero content higher, reduces its maximum headline from 176px to 140px, tightens headline/action gaps, and moves the full dossier upward. The Archive's desktop headline maximum moves from 148px to 116px; its left column starts higher and no longer distributes content to opposite ends of its tall column. These changes target first-view action visibility while preserving the large case-file art. They use a `min-width:1051px` rule so the prior stacked/zoom and phone layouts remain governed by their own rules. No fixed content height, clipping, hidden text or absolute-positioned entry action was added. The supplied screenshots predate these refinements; first-view action visibility after the change is **unverified** until a new capture.

A further owner screenshot batch showed those desktop refinements were insufficient: Signal / Noise revealed only the top edge of its action at 900px height, and The Archive still placed its action below the first viewport. The desktop-only rule now moves Signal / Noise's top content from 145px to 100px, caps its headline at 124px instead of 140px, tightens heading/action gaps, and allows its opening copy to use 560px rather than 480px so it may wrap into fewer lines. The Archive's left content begins at 26px rather than 48px; its headline maximum becomes 96px rather than 116px, gaps shrink, and the lead can use 750px rather than 630px. This seeks roughly 100px of vertical savings without moving either action out of normal document flow. Both case-file illustrations remain unchanged, and the `max-width:1050px` layouts remain untouched. The new desktop rendering and actual CTA visibility remain **unverified**; the screenshots document the state before this latest adjustment.

The owner supplied two refreshed opening captures after the second desktop adjustment. At the approximately 1800px-wide captured desktop view, both full entry actions are visible without scrolling. Signal / Noise has comfortable space below its action; The Archive's action is visible near the bottom edge. This verifies first-screen action visibility **only for these captured desktop conditions**. Shorter desktop heights, 200% zoom, phone layouts, keyboard operation, contrast, motion, and live gameplay remain unverified.

## Review status

Visual Design authored both files. Coordinator source review found that the original skip link used inline focus handlers despite the no-JavaScript claim; Visual Design replaced those handlers with CSS focus styling in both files. Independent QA then found invented Friday-release/checklist content; Visual Design aligned the copy to KB-01/02/03 and replaced the self-linking interpretation CTA with an explicitly concept-only display. QA's final source review found that the evidence view could imply pre-interview access and re-asked already obtained facts; Visual Design labelled it post-interview and changed the prompts to next-step questions. The coordinator independently source-reviewed the responsive and desktop revisions after the owner's screenshots; no new source-level blocker was found. The agent's in-app browser later blocked local file navigation by security policy. The latest owner captures verify desktop first-screen action visibility under the captured conditions. The author has not self-approved either direction. The next step is to record owner direction, then test the chosen direction at narrower widths and 200% zoom during implementation.
